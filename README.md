# تحدّي صنّاع الأثر — NextStep AI

موقع ثابت (HTML) + قاعدة بيانات Supabase. يُنشر مجاناً على GitHub Pages.

## الصفحات (كلها في index.html)
| الرابط | الصفحة |
|---|---|
| `/` | لوحة الصدارة (أفضل 5) والبحث برقم العضوية |
| `/#join` | تسجيل المشاركين |
| `/#rules` | قواعد التحدّي |
| `/#admin` | لوحة الفريق (بتسجيل دخول) |
| `/?c=رقم_العضوية` | الصفحة الشخصية للمشارك |

## 1) قاعدة البيانات (Supabase)
1. أنشئ مشروعاً في supabase.com.
2. SQL Editor ← الصق محتوى `supabase/schema.sql` كاملاً ← Run.
3. Authentication ← Providers ← Email ← عطّل **Sign ups**.
4. Authentication ← Users ← أنشئ حسابات الفريق الأربعة يدوياً.
5. Authentication ← URL Configuration ← ضع رابط موقعك على GitHub Pages في Site URL.
6. Project Settings ← API ← انسخ Project URL ومفتاح **anon public** إلى `config.js`.

## 2) النشر على GitHub Pages
1. أنشئ مستودعاً جديداً (مثلاً `impact-challenge`) وارفع كل محتويات هذا المجلد.
2. Settings ← Pages ← Source: **Deploy from a branch** ← `main` / `(root)` ← Save.
3. بعد دقيقة يصبح الموقع على: `https://USERNAME.github.io/impact-challenge/`

## 3) قبل الإطلاق
- المواعيد الحالية في `config.js`: من السبت 3 أكتوبر 2026 إلى الخميس 8 أكتوبر 8 مساءً بتوقيت غزة (UTC+3). إن غيّرتها فعدّل أيضاً نصوص «جدول التحدّي» و«القواعد» داخل `index.html`.
- جرّب مع 5 إلى 8 أشخاص: تسجيل مكرر، إحالات متتابعة، دخول الأدمن بحساب غير مصرّح.
- ادخل `/#admin` وتأكد أن تسجيل الدخول يعمل وأن الأرقام تظهر في الصفحة العامة.

## ملاحظات
- بدون بيانات Supabase في `config.js` يعمل الموقع بوضع تجريبي ببيانات وهمية.
- بيانات المشاركين الشخصية لا تظهر للجمهور، لكن قاعدة الأمان تعتمد على تعطيل Sign ups. لا تتركه مفعّلاً.
- إن ظهر تسجيل مزيف كثير فعّل CAPTCHA من إعدادات Supabase.

## الصور الشخصية
- يرفع المشارك صورته عند التسجيل (تُقصّ وتُضغط تلقائياً إلى 320×320 JPEG داخل المتصفح).
- تُخزَّن في Supabase Storage داخل حاوية `avatars` يُنشئها `schema.sql` تلقائياً. لا تحتاج أي إعداد يدوي.
- يُسمح بصورة واحدة لكل مشارك ولا يمكن استبدالها من الخارج. وتظهر علناً بجانب اسمه الأول.
- يستطيع الفريق إزالة أي صورة غير لائقة من لوحة الأدمن ← المشاركون ← «إزالة الصورة».

## روابط مختصرة (ملفات إعادة توجيه)
`admin.html` ← لوحة الأدمن · `join.html` ← التسجيل · `rules.html` ← القواعد
(مثال: `https://USERNAME.github.io/اسم-المستودع/admin.html`)

## الكود الشخصي
رقم عضوية المشارك في مجتمع NextStep هو كوده الشخصي في التحدّي (للبحث عن أثره وللإحالات). لا تُولَّد أكواد منفصلة.

## ربط التحدّي بقاعدة بيانات العضويات
- الموقع يعمل على **نفس مشروع Supabase** الذي تعمل عليه صفحة العضويات، ويقرأ جدول `members` الذي تنشئه الدالة `create_member` تلقائياً. أي شخص ينشئ عضويته يصبح رقمه موجوداً فوراً ويستطيع التسجيل في التحدّي.
- عند التسجيل يتحقق النظام من: وجود رقم العضوية في `members`، ومطابقة البريد الإلكتروني لبريد العضوية (حتى لا يستخدم أحد رقم غيره)، وعدم تكرار الرقم أو الهاتف.
- أثناء كتابة رقم العضوية يظهر فحص فوري (موجود ✓ / غير موجود / مسجّل مسبقاً).
- لوحة الأدمن ← تبويب **الأعضاء**: عدد الأعضاء في القاعدة، وبحث للتحقق من أي رقم.
- `schema.sql` يتوقف برسالة واضحة إن لم يجد جدول `members` والعمود `membership_number`. لا يعدّل على الجدول ولا يفتحه للعامة، ويضيف فقط سياسة قراءة لحسابات الفريق المسجّلة.
- تأكد من تفعيل Row Level Security على جدول `members` كما توصي به صفحة العضويات.

## الإدخال اليومي للإحالات
تبويب **إدخال** ← «إدخال دفعة يومية»: سطر لكل طالب جديد:
`الاسم الثلاثي | رقم عضوية من دعاه | الجامعة | الهاتف`
(يمكن لصق الأعمدة من Excel مباشرة). ثم راجعها وأكدها من تبويب **المراجعة**.

## الروابط
عدّلها من `LINKS` في `config.js` (صفحة العضويات، واتساب، إنستغرام، لينكدإن).
